### 3.3 不采纳项与理由

| 来源 | 要点 | 不采纳理由 |
| --- | --- | --- |
| linkchecker | 输出 SQL / sitemap graph / HTML 报告等 6+ 格式 | 桌面工具用户以 Excel/JSON 后处理为主；每多一个格式都增加导出回归面，当前 TXT/CSV/JSON 已覆盖实际需求 |
| linkchecker | 检查插件体系（SSL 证书细粒度策略等） | 引入插件框架超出单机桌面工具的维护预算；现有 `_SSLAdapter` 遗留服务器兼容开关已覆盖同类需求 |
| lychee | GitHub Action 分发形态 | 本项目定位桌面端工具，CI 集成形态与产品定位不符 |
| hydra | YAML 报告输出 | JSON 已提供等价的机器可读能力，避免新增解析器依赖（依赖最小化红线） |

## 4. 取舍原则备忘

1. **同轴优先**：只对标「链接提取 + 体检」同轴项目，图片/小说/电商爬虫不做功能对标。
2. **等价即不动**：凡本项目已有等价实现（即使实现方式不同），一律不改动，避免无回归收益的扰动。
3. **默认值零变化**：新增 CLI 参数不得改变无参数时的历史行为（本轮 `--version` / `-h` 满足）。
4. **依赖最小化**：不为单个借鉴点引入新依赖（本轮全部落地项零新依赖）。
5. **测试可无 GUI 运行**：核心层测试不得依赖 tkinter / 网络，保证任意环境可回归。

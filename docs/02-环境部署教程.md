### 3.2 安装命令

**方式一：pip 安装（推荐，自动注册 `weblinkcrawler` 命令）**

```bash
# 建议使用独立虚拟环境，避免与共享解释器里的无关包相互干扰
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux

python -m pip install -r requirements.txt
python -m pip install -e .      # 注册 weblinkcrawler 命令与 python -m 入口
```

**方式二：仅安装依赖，直接用模块方式启动**

```bash
python -m pip install -r requirements.txt
# 无需 pip install -e .，直接从项目根目录执行：
python -m weblinkcrawler
```

> `pyproject.toml` 的 `[project.scripts]` 注册了 `weblinkcrawler = weblinkcrawler.app:main` 入口点；`src/weblinkcrawler/__main__.py` 支持 `python -m weblinkcrawler`。两种方式等价，均调用 `weblinkcrawler.app:main`。

### 3.3 环境一致性核对（必做）

```bash
python -m pip list
python -m pip check
```

逐项与 `requirements.txt` 比对。若发现版本漂移（如 urllib3 实装 2.7.0 而清单锁 2.8.0），执行：

```bash
python -m pip install -U "urllib3==2.8.0"
```

## 4. 启动

### 4.1 启动命令

```bash
# 在项目根目录执行（二选一）
python -m weblinkcrawler          # 模块方式
weblinkcrawler                     # pip install -e . 后的命令方式
```

`__main__.py` 与 `pyproject.toml` 入口点均转发至 `weblinkcrawler.app:main`。**配置与数据库按当前工作目录读写，请始终从项目根目录启动**，以保持配置和数据库位置稳定。

### 4.2 首次运行行为

| 文件 | 行为 | 代码位置 |
| --- | --- | --- |
| `enhanced_config.json` | 不存在则按 `DEFAULT_ENHANCED_CONFIG` 生成；已存在但缺键则深合并补齐并回写 | `config.py` `load_enhanced()` |
| `file_type_config.json` | 不存在则按 `DEFAULT_FILE_TYPE_MAPPING` 生成 | `config.py` `load_file_types()` |
| `crawling_progress.db` | 创建三张表（`crawling_tasks` / `crawled_links` / `link_checks`）+ 索引，WAL 模式、`busy_timeout=30000`；旧库自动补齐缺失列 | `database.py` |
| `weblinkcrawler.log` | 创建分级文件日志（INFO 及以上，同时输出控制台） | `logutil.py` |

启动后默认停在「任务布设」页。

### 4.3 打包运行（`sys.frozen`）

以 PyInstaller 等方式打包运行时，网页预览**不启动独立子进程**，自动改用内置降级预览（`app.py` 检测 `sys.frozen` 后走降级路径）。

## 5. 可选：PyQt5 WebEngine 预览

真实网页预览与元素点选需要 PyQt5 + QtWebEngine：

```bash
python -m pip install -r requirements-preview.txt
# 或：python -m pip install -e ".[preview]"
```

| 包 | 锁定版本 |
| --- | --- |
| PyQt5 | 5.15.11 |
| PyQtWebEngine | 5.15.7 |

- **版本匹配要求**：PyQtWebEngine 需与 PyQt5 版本匹配。
- **探测方式**：程序启动时用 `importlib.util.find_spec("PyQt5")` 并检查 `QtWebEngineWidgets` 扩展文件是否存在，**不在主进程创建 Qt 环境**（`app.py` `_qt_webengine_available()`）。
- **验证是否生效**：打开「参数配置 → 环境信息」，看「网页预览能力」一行：
  - `PyQt5 + QtWebEngine 可用` → 按钮文案为 `网页预览选元素`；
  - `未安装 PyQt5/QtWebEngine，使用内置降级预览` → 按钮文案为 `网页预览选元素（降级）`，点击后使用内置 HTML 结构预览。
- 未安装时**主要功能不受影响**：抓取、筛选、体检、导出、CSS 选择器手工填写均正常。

## 6. 配置文件说明

配置文件均为 JSON，位于启动目录（绝对路径见「参数配置 → 环境信息」）。

- 通过「增强功能配置」窗口修改并保存后，**对下一次抓取立即生效**（`ConfigManager` 把配置常驻内存，抓取引擎在每次抓取时实时读取取值）。
- 直接手工编辑 `enhanced_config.json` **需重启程序后生效**——程序只在启动时读取一次该文件。
- 唯一在界面构建期读取的键是 `multi_url.enabled`（决定多行/单行输入形态），改动它必须重启。

**权限**：`save_enhanced()` 在 POSIX 下把文件置为 `0600`；Windows 上由文件系统 ACL 决定。

### 6.3 数据库 `crawling_progress.db`

| 表 | 用途 | 关键列 |
| --- | --- | --- |
| `crawling_tasks` | 抓取任务 | `id, url, depth, status, start_time, end_time, total_links, crawled_links` |
| `crawled_links` | 已发现链接 | `id, task_id, url, link, depth, status, file_name, file_type, file_size, last_modified, crawled_at` |
| `link_checks` | 体检结果 | `id, task_id, link, state, status_code, checked_at` |

全部 SQL 参数化；DDL 迁移只使用模块内常量表名/列名并过标识符白名单。任务状态 `pending`/`crawling`/`stopped` 视为未完成，可断点续爬。

## 7. 故障排查

| # | 现象 | 可能原因 | 处置 | 依据 |
| --- | --- | --- | --- | --- |
| 1 | `ModuleNotFoundError: No module named 'weblinkcrawler'` | 未从项目根目录启动，或未将 `src` 加入路径 | 在项目根目录执行 `python -m weblinkcrawler`；或先 `pip install -e .` | `__main__.py`、`pyproject.toml` |
| 2 | 启动即 `TclError: couldn't read file .../tcl/tk8.6/ttk/ttk.tcl` | 环境瞬时读取失败（实测过一次：该文件存在且 `tkinter.Tk()` 可正常初始化，重跑三次均通过） | 重新启动；若持续出现，重装/修复 Python 的 tcl/tk 组件 | `05-开发日志.md` |
| 3 | 窗口无图标 / 按钮只剩文字 | 旧版 `icons.photo()` 的 `PhotoImage.put` 传入扁平颜色列表导致图标不渲染（v0.1.0 已修复） | 升级到 v0.1.0 代码 | `05-开发日志.md` V-01 |
| 4 | 「网页预览选元素（降级）」且预览打不开真实网页 | PyQt5 或 QtWebEngineWidgets 未安装 / 版本不匹配 | `python -m pip install -r requirements-preview.txt`；在「参数配置 → 环境信息」确认能力行 | `app.py` `_qt_webengine_available()` |
| 5 | 预览窗口 3 分钟无响应后被关闭 | 轮询上限 600 次 × 300ms ≈ 3 分钟 | 缩短为可正常加载的页面；日志记 `网页预览超时（约 3 分钟），已关闭预览进程。` | `app.py` 预览轮询 |
| 6 | 预览子进程启动失败并回退 | 打包环境（`sys.frozen`）或不支持子进程 | 属预期降级，日志记 `已切换到降级预览` | `app.py` |
| 7 | 抓取结果为空，日志大量 `[robots拒绝]` | 站点 robots.txt 禁止抓取 | 确认策略后可关闭 `network_policy.respect_robots`（需自行承担合规责任） | `crawler.py` |
| 8 | 日志出现 `[跳过解析] … 非可解析内容类型` | Content-Type 不在白名单（JSON/二进制/媒体） | 需要时把类型加入 `content_gate.parseable_content_types` | `crawler.py` `_should_parse_body` |
| 9 | 日志出现 `[429 限流] … 秒后重试` / `[放弃重试]` | 目标站限流 | 调大 `request_strategy.interval` / `retries` / `retry_after_cap`；429 错误页链接不会被计入结果 | `crawler.py` `_fetch_with_retry` |
| 10 | 体检大量「异常」 | HEAD 被站点拒绝 | 默认对 405/501 回退只读 GET；仍异常可把 403 纳入回退（`link_check.head_fallback_include_403=true`，注意可能是真实鉴权拦截） | `crawler.py` `check_links` |
| 11 | `写入 enhanced_config.json 失败，请检查文件权限。` | 启动目录只读 / 文件被占用 | 以可写权限启动，或改用可写目录；POSIX 下保存会尝试 `chmod 0600` | `app.py`、`config.py` |
| 12 | 数据库繁忙或写入失败 | 多线程并发写 | 已用单连接 + `threading.Lock` + WAL + `busy_timeout=30000` 缓解；失败仅记日志不中断抓取 | `database.py`、`crawler.py` |
| 13 | GBK 编码的 URL 清单导入乱码/失败 | 清单非 UTF-8 | 已自动按 `utf-8-sig → utf-8 → gb18030 → gbk → big5 → latin-1` 尝试解码 | `app.py` `import_urls` |
| 14 | `pip check` 报 pillow / matplotlib 等冲突 | 共享解释器里存在无关包 | 使用虚拟环境；本项目依赖与这些包无关 | 环境实测 |
| 15 | urllib3 版本与清单不一致 | 环境漂移（安全审计 D-01，高） | `python -m pip install -U "urllib3==2.8.0"` 后复跑 `pip check` | `requirements.txt` |

## 8. 升级说明

### 8.1 从 v0.6 及更早版本升级

| 项 | 行为 |
| --- | --- |
| 入口命令 | 由 `python WebLinkCrawler.py` 改为 `python -m weblinkcrawler`（或 `weblinkcrawler` 命令） |
| 代码结构 | 单文件 → `src/weblinkcrawler` 包 |
| 配置 | 旧 `enhanced_config.json` 直接可用，缺键自动补齐并回写，无需手工修改 |
| 数据库 | 沿用旧表结构，新增 `link_checks` 表；旧 `crawling_progress.db` 可直接使用，启动时自动补齐缺失列 |
| 主题 | 默认「宣纸·墨黛」；仅浅色主题，无暗色主题 |
| 建议 | 升级前备份 `enhanced_config.json` 与 `crawling_progress.db` |

### 8.2 升级步骤

```bash
# 1. 备份配置与数据库
copy enhanced_config.json enhanced_config.json.bak
copy crawling_progress.db crawling_progress.db.bak

# 2. 安装依赖并注册入口
python -m pip install -r requirements.txt
python -m pip install -e .

# 3. 启动
python -m weblinkcrawler
```

## 9. 卸载

1. 关闭程序（若抓取中会弹确认框）。
2. 删除项目目录；如需保留数据，先备份 `crawling_progress.db` 与 `enhanced_config.json`。
3. 虚拟环境：删除 `.venv/` 目录即可；共享解释器可用 `python -m pip uninstall -r requirements.txt -y` 逐个卸载（注意勿影响其他项目）。若曾执行 `pip install -e .`，先 `python -m pip uninstall weblinkcrawler`。
4. 运行产物 `weblinkcrawler.log`、`%TEMP%\wlc_preview_*.json` 可一并清理。

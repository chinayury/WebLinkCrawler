## 1. 项目定位

WebLinkCrawler（网页链接抓取工具）是一款面向**运维巡检、内容整理与站点体检**场景的桌面端工具。输入一个或多个网址，即可提取页面中的链接，按文件类型、协议、关键词筛选，支持同域深度抓取、反反爬请求策略、断点续爬、CSS 元素区域限定、链接存活体检，以及 TXT / CSV / JSON 结构化导出。

**v0.1.0 为正式稳定版**，是该项目的版本纪元起点，覆盖此前 v0.1–v0.6 开发迭代编号，v0.6 全部功能均已保留。当前视觉体系为「**宣纸·墨黛**」（Rice Paper & Ink），全浅色、无暗色主题、无背景图。

## 2. 核心能力

| 模块 | 能力 |
|---|---|
| 多目标抓取 | 单 / 多 URL，支持导入（UTF-8 / GBK / GB18030 / BIG5 自动识别）、导出、格式校验与去重 |
| 多维筛选 | 单选 / 多选文件分类、HTTPS / HTTP、关键词（子串 / 正则） |
| 区域限定 | CSS 选择器限定抓取范围；PyQt5 网页预览点选（未安装时降级为 HTML 结构点选） |
| 深度抓取 | 同域 BFS，0–5 级可配，有界并发（1–64）与最大页数上限（1–100000） |
| 请求策略 | 动态 UA、HTTP / SOCKS5 代理、Cookie、per-host 请求节流 / 重试 / 超时与指数退避（429 / 503 / 408 支持 Retry-After） |
| 爬虫礼仪 | 可选 robots.txt 遵循（`*` 通配、`$` 锚定、Allow 最长优先）与 Crawl-delay |
| 排除规则 | 通配 / 正则，抓取阶段即过滤噪声链接 |
| 文件过滤 | 按 Content-Length（MB）与 Last-Modified（天）过滤，并发探测 |
| 去重口径 | raw URL + canonical key 双轨制；query 噪声参数黑白名单（白名单优先，保护真分页参数） |
| 断点续爬 | SQLite 持久化任务与已访问页面，恢复时跳过已访问页面、合并已有结果 |
| 链接体检 | 并发 HEAD 校验（HEAD 被拒时回退只读 GET），五级分级（可用 / 重定向 / 受限 / 失效 / 异常），结果入库 |
| 结构化导出 | TXT（兼容旧版式）、CSV（utf-8-sig，Excel 友好）、JSON（含元信息） |
| 视觉体系 | 「宣纸·墨黛」浅色工作台，3 套配色方案，35 个自绘「墨线」线性图标 |
| 安全边界 | 协议 / 主机校验、逐跳重定向校验、私有地址拦截、响应体上限、参数化 SQL、DDL 标识符白名单、日志脱敏 |

## 4. 模块结构与分层

源码位于 `src/weblinkcrawler/`，采用标准 src 布局，包目录名与发行名一致。模块按职责分层：

```
src/weblinkcrawler/
├── __init__.py      # 版本元数据（APP_VERSION 等，唯一版本来源）
├── __main__.py      # python -m weblinkcrawler 入口，转发至 app.main
├── app.py           # GUI 组装与交互（2390 行：左导航 + 四页面板 + 对话框）
├── crawler.py       # 抓取 / 体检 / 导出引擎（1792 行）
├── config.py        # 配置合并、校验、URL 规范化与 canonical key（580 行）
├── database.py      # SQLite 持久化与 DDL 迁移（244 行）
├── security.py      # 网络边界校验：validate_target / is_private_host（94 行）
├── preview.py       # 可选 PyQt5 元素选择子进程（422 行）
├── theme.py         # 视觉体系与 3 套配色方案（456 行）
├── icons.py        # 自绘「墨线」线性图标，35 个（487 行）
└── logutil.py      # 分级日志（37 行）
```

### 分层原则

| 层 | 模块 | 职责 | 依赖方向 |
|---|---|---|---|
| 表现层 | `app.py` | GUI 组装、事件队列、对话框、导入导出交互 | 调用引擎层与配置层 |
| 引擎层 | `crawler.py` | 抓取调度、请求/重定向/robots/节流/体检/导出 | 调用安全层、配置层、数据库层 |
| 策略层 | `config.py`、`security.py` | 配置合并取值、URL 规范化校验、网络边界判定 | 被引擎层与表现层调用，不反向依赖 |
| 持久层 | `database.py` | SQLite 任务/链接/体检结果存储 | 被引擎层调用 |
| 支撑层 | `theme.py`、`icons.py`、`logutil.py`、`preview.py` | 视觉、图标、日志、预览子进程 | 被表现层与引擎层调用 |

**依赖约束**：模块间使用相对导入（`from . import ...`），包内可解析；策略层与持久层不依赖表现层，避免循环依赖。

## 5. 核心设计原则

1. **配置驱动**：抓取深度、并发、过滤、反反爬等取值全部来自 `enhanced_config.json`，由 `ConfigManager` 深合并校验，缺键自动补齐，不因缺键崩溃。
2. **线程安全**：后台抓取/体检在工作线程执行，所有 Tk 控件操作经线程安全队列回主线程，GUI 元素只在主线程读写。
3. **安全优先**：网络边界逐跳校验、私有地址拦截、响应体上限、参数化 SQL、DDL 标识符白名单、日志脱敏，详见 `04-安全设计说明.md`。
4. **降级可用**：PyQt5 WebEngine 未安装时自动降级为 HTML 结构预览，主要功能不受影响；打包环境（`sys.frozen`）下预览子进程不启动，走降级路径。
5. **断点续爬**：任务与已访问页面实时入库，停止后可恢复，跳过已访问页面、合并已有结果。
6. **文档与代码同步**：设计文档随代码迭代更新，路径、命令、模块名、参数均可在真实目录中对应。

## 6. 数据流

一次完整抓取的数据流如下：

```
用户输入 URL（任务布设页）
        │
        ▼
  ConfigManager（加载/校验配置）──► enhanced_config.json / file_type_config.json
        │
        ▼
  CrawlerEngine.crawl()（后台线程）
        │  ├─ _perform：逐目标请求（安全校验 → 请求 → 解析）
        │  ├─ _crawl_round：BFS 同域下钻（深度/页数/并发上限）
        │  ├─ _normalize_links：去重（raw URL + canonical key 双轨）
        │  └─ DatabaseManager：任务/链接实时入库
        ▼
  结果清册页（表格 / 文本双视图，可排序、筛选）
        │
        ▼
  链接体检（并发 HEAD，HEAD 被拒回退只读 GET）
        │
        ▼
  导出（TXT / CSV / JSON，写当前筛选结果）
```

## 7. 视觉体系

**「宣纸·墨黛」（Rice Paper & Ink）** —— 全浅色、无暗色主题、无背景图。

- **色相族**：近单色「墨」+ 单一「朱印」。主色中性墨 `#22262B`，强调色朱印 `#B03A2E` 仅用于品牌标记、每页唯一主操作按钮与失效计数；画布宣纸白 `#FAF8F3`、面板纯白 `#FFFFFF`、凹陷区 `#F1EEE6`。
- **导航**：浅色纸底 `#F5F2EA` + 右侧 1px 边线；激活项用 2px 朱红左杠 + 加粗文字；分组为「作业 / 观测 / 整备」。
- **面板**：通栏纸底标题带 + 底部 1px 细线，层级靠字重与字号表达。
- **按钮三档**：实底墨色 / 1px 描边 / 纯文字链（`Ghost.TButton`）。
- **表格**：只保留横向细线（无竖线、无斑马纹），行高 30。
- **语义色降饱和**：成功 `#3F7A4E` / 警示 `#A87A16` / 危险 `#A8443C` / 信息 `#4A6E8A`，使五级链接状态色成为近单色画布上唯一高饱和信号。
- **配色方案**：固定 3 套循环切换（宣纸·墨黛默认 / 黛蓝·琥珀 / 陶红·亚麻）。
- **图标**：35 个纯 Python 自绘「墨线」线性图标——1.6 / 1.2 / 1.9px 三级笔宽、圆头圆角、24×24 网格 2px 内缩、圆角容器；3×3 超采样软件光栅化，无第三方图像依赖。
